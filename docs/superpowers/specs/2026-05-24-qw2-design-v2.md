# QW-2 v2 — RAW → Topic Files (Sem SSOT)

**Data:** 2026-05-24
**Revisões:** 2026-05-24 (fact-check + review Lincoln)
**Status:** Draft → Pending Review
**Autor:** Lincoln + Livy
**Decisão central:** Descartar o SSOT como layer intermediária. RAW sources são completas e atualizadas — SSOT adicionava complexidade sem valor.

---

## 1. Motivação

**Problema:** O SSOT não justifica a complexidade.

| Fato | Implicação |
|---|---|
| 99.9% das 2,221 claims têm `topic_id=null` | Routing nunca funcionou |
| 482 decisões Trello são "Card 'X' foi concluído (DONE)" | Ruído massivo, não decisões |
| ~55 decisões TLDV reais (10%) são ouro | O resto é descartável |
| SSOT é cache stale — desatualiza entre runs | RAW é sempre a verdade |

**Decisão:** QW-2 consulta RAW diretamente. Menos ETL, menos bugs, mais honesto.

## 3. QW-2 — RAW → Topic File Pipeline

### 3.1 Filtros de Qualidade (ANTES do routing)

Primeira coisa: descartamos o que não vale processar.

```python
import re

DONE_CARD_RE = re.compile(
    r"foi conclu[ií]d[oa].*\nlista\s*:",
    re.IGNORECASE | re.DOTALL
)

def should_skip(claim: dict) -> tuple[bool, str]:
    text = claim.get("text", "")

    # 1. DONE card notifications — não é decisão
    if DONE_CARD_RE.search(text):
        return True, "Trello DONE card"

    # 2. Texto curto demais
    if len(text) < 50:
        return True, f"text too short ({len(text)} chars)"

    # 3. Confiança baixa
    confidence = claim.get("confidence", 0)
    if confidence < 0.75:
        return True, f"low confidence {confidence}"

    # 4. TLDV sem decisões registradas
    if "sem decisões registradas" in text.lower():
        return True, "no decisions in transcript"

    return False, ""
```

**Nota:** `re.DOTALL` faz o `.` casar com newlines — cobre `foi concluído.\n\nLista:` e variações com quebras.

### 3.2 Filtros por Fonte

#### Trello — Board Allowlist

**28 boards existem; sem filtro, processa tudo.** Allowlist hardcoded:

```python
ALLOWED_BOARDS = {
    "BAT",           # ConectaBot observability
    "Delphos",       # Video vistoria
    "Forge",         # Living Forge Platform
    "KABA",          # Projeto KABA
    "4D Imobi",      # Imobiliário
    "Hydra",         # Hydra evolution
    "Living",
}
```

Boards fora da allowlist são **silenciados** — processados no cursor mas não geram pending/writes. Boards irrelevantes (Alexandre, Financeiro, RH) são ignorados sem erro.

#### TLDV — Meeting Name Filter

Reuniões de status são filler. Filtro por padrão:

```python
STATUS_MEETING_RE = re.compile(
    r"^Status\s+(KABA|BAT|BOT)",
    re.IGNORECASE
)

def should_skip_meeting(meeting_name: str) -> bool:
    # Status meetings são filler — pulamos se não tiverem decisions reais
    if STATUS_MEETING_RE.match(meeting_name):
        return True  # will be overridden if transcript has high-confidence decisions
    return False
```

**Override:** Se TLDV meeting passar nos filtros E confidence ≥ 0.90, **mesmo** que seja Status meeting. A decisões genuínas sobre "foi decidido que..." aparecem em Status meetings.

### 3.3 Routing (Inference Pass)

Para cada claim que passou nos filtros:

**TLDV:**
- Meeting name → project/topic
- Topics do transcript → tags

**Trello:**
- Board name → project (via allowlist)
- Card title → subject
- Labels → tags

**GitHub:**
- Repo → project
- PR title → subject
- PR body → decision content

**Routing rules (case-insensitive):**
```
bat, kaba, bot         → bat-conectabot-observability.md
tldv, memory, livy,
openclaw, gateway       → livy-memory-agent.md
delphos, vistoria     → delphos-video-vistoria.md
forge                  → forge-platform.md
evo, evolution         → livy-evo.md
4d, imobi             → 4d-imobi.md
hydra                  → hydra-evolution.md
```

**Fallback:** Se nenhum match → `general.md` + **DM a Lincoln** (routing falhou).

### 3.4 Write Log (Dedupe + Rollback)

**Dedupe:** Antes de escrever, verificar se `source_ref` já foi processado.

```python
# written_refs.json — set de source_refs já escritos
{
  "tldv:meeting_id_abc123",
  "trello:card_id_xyz",
  "github:pr_456"
}
```

**Write log:** Cada write é registado no `write_log.jsonl`.

```json
{"ts": "2026-05-24T07:00:00Z", "source_ref": "tldv:meeting_id", "topic": "bat-conectabot-observability.md", "action": "append"}
```

**Rollback:** Se topic file ficou corrupto, `python rollback.py --last N` lê o write log e remove os últimos N entries.

### 3.5 Topic File Write (Direct, com dedupe)

```python
def write_decision(topic_file: str, decision: dict):
    source_ref = decision["source_ref"]

    # Dedupe
    if source_ref in load_written_refs():
        return  # already written

    # Append as blockquote no topic file
    entry = f"""
### {decision['date']} — {decision.get('source', 'unknown')}

> {decision['text']}

- **Source:** {decision.get('source_ref')}
- **Confidence:** {decision['confidence']}
- **Tags:** {', '.join(decision.get('tags', []))}
"""
    with open(topic_file, 'a') as f:
        f.write(entry)

    # Register
    add_to_written_refs(source_ref)
    append_to_write_log(source_ref, topic_file, "append")
```

## 4. QW-3 — Exceções e Revisão (Minimal)

### 4.1 O que ainda precisa de approval?

| Caso | Condição | Ação |
|---|---|---|
| **Decisão TLDV ambígua** | `confidence < 0.85` E routing OK | DM Lincoln |
| **Topic inferido como `general`** | routing falhou | DM Lincoln |
| **Primeiro run** | sempre dry-run | DM com resultado → Lincoln confirma |

### 4.2 Regra: Primeiro Run é Sempre Dry-Run

**Risco:** Bug no filter → write direto → topic file corrupto para todos os users.

**Mitigação:** O **primeiro run** de QW-2 é sempre dry-run. Resultado vai para DM a Lincoln. Só após Lincoln confirmar (`confirm_run` callback) é que runs subsequentes escrevem para valer.

```python
def is_confirmed() -> bool:
    """Check if previous run was confirmed."""
    return Path(".research/qw2/.confirmed").exists()
```

Se não confirmado: dry-run, DM com resultado, nenhuma escrita.

### 4.3 Routing DM vs Silencioso

| Condição | Ação |
|---|---|
| `confidence < 0.85` E `source == tldv` | DM com ✅confirmar/❌rejeitar |
| routing falhou (topic=general) | DM com topic sugerido |
| ≥ 1 decision routing failed | agrupar num DM só |
| confidence ≥ 0.85 E routing OK | **silencioso** (write direto) |

### 4.4 DM Format

```
🔍 QW-2 result — pending confirmation

Decisões geradas: 3
Fontes: TLDV (2), GitHub (1)
Topics: bat (1), forge (2)

[✅ Confirmar — proximo run escreve] [❌ Cancelar]

Dry-run output:
  • [TLDV] "Cloud foi identificado como melhor opção..." → bat-conectabot
  • ...
```

### 4.5 Callback Handlers (Idempotentes)

```python
def handle_confirm(claim_id: str) -> str:
    # Idempotente: se já confirmado, não faz nada
    if is_confirmed():
        return "already_confirmed"
    Path(".research/qw2/.confirmed").touch()
    return "confirmed"

def handle_reject(claim_id: str) -> str:
    # Idempotente: se já rejeitado, não faz nada
    if is_rejected(claim_id):
        return "already_rejected"
    archive_pending(claim_id)
    return "rejected"
```

## 6. CLI Interface

```bash
# Dry-run (primeiro run — default)
python run.py [--dry-run] [--source tldv|trello|github|all]

# Run para valer (só após confirmação)
python run.py --confirm-run [--source tldv|trello|github|all]

# Rollback
python rollback.py --last N       # reverte últimos N writes
python rollback.py --topic <file> # reverte writes num topic específico

# Status
python run.py --status           # mostra cursor, written_refs, pending
```

**Flags:**
- `--dry-run` — default no primeiro run, pode ser usado sempre
- `--source tldv` — testa só uma fonte (mais útil que dry-run total)
- `--confirm-run` — requer que `.research/qw2/.confirmed` exista

## 8. TDD — Tabela de Testes do Filter

### test_filter.py

```python
import pytest
from vault.qw2.filter import should_skip, DONE_CARD_RE

@pytest.mark.parametrize("text,expected_skip,reason", [
    # DONE card variants
    ("Card 'X' foi concluído.\n\nLista: DONE", True, "standard DONE pattern"),
    ("Card 'X' foi concluída.\n\nLista: Done", True, "capitalisation variant"),
    ("foi concluído.\n\nLista:", True, "minimal DONE pattern"),
    ("Card 'X' foi concluído.\n\nLista:;", True, "semicolon variant"),
    ("Card 'X' foi concluído.\nLista:", False, "no newline before lista — not DONE format"),
    ("foi decidido que...", False, "real decision — not DONE"),
    # Length
    ("x" * 49, True, "49 chars — too short"),
    ("x" * 50, False, "50 chars — exact threshold"),
    ("x" * 51, False, "51 chars — OK"),
    # Confidence
    ({"text": "x" * 51, "confidence": 0.74}, True, "confidence below 0.75"),
    ({"text": "x" * 51, "confidence": 0.75}, False, "confidence at threshold"),
    # No decisions
    ("Sem decisões registradas", True, "TLDV no-decisions placeholder"),
    ("sem decisões registradas", True, "lowercase variant"),
])
def test_should_skip(text, expected_skip, reason):
    if isinstance(text, dict):
        skip, _ = should_skip(text)
    else:
        skip, _ = should_skip({"text": text, "confidence": 0.90})
    assert skip == expected_skip, reason
```

## 11. Riscos e Mitigações

| Risco | Severidade | Mitigação |
|---|---|---|
| Bug no filter → write corrupto | **Crítico** | **Primeiro run dry-run + confirmação DM** — só após `confirm_run` é que escreve |
| DONE card filter bypass | **Menor** | Regex `re.DOTALL` cobre variantes com newlines |
| Topic file duplication | **Mediano** | `written_refs.json` dedupe por `source_ref` — não re-escreve |
| QW-3 callback loss (crash between receive/write) | **Mediano** | Callback handlers **idempotentes** — retry-safe |
| Topic file corrupto pós-write | **Menor** | `write_log.jsonl` + `python rollback.py --last N` |
| Trello boards irrelevantes processados | **Menor** | **Board allowlist** — só 7 boards Living |
