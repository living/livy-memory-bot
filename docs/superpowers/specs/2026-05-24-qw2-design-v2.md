# QW-2 v2 — RAW → Topic Files (Sem SSOT)

**Data:** 2026-05-24
**Status:** Draft → Pending Review
**Autor:** Lincoln + Livy
**Decisão central:** Descartar o SSOT como layer intermediária. RAW sources são completas e atualizadas — SSOT adicionava complexidade sem valor.

---

## 1. Motivação

**Problema:** O SSOT não justifica a complexidade.

| Fato | Implicação |
|---|---|
| 99.9% das 2,221 claims têm `topic_id=null` | Routing nunca funcionou |
| 482 decisões Trello são "Card 'X' foi concluído (DONE)" | Ruído massivo, não decisões |
| 55 decisões TLDV reais (10%) são ouro | O resto é descartável |
| SSOT é cache stale — desatualiza entre runs | RAW é sempre a verdade |

**Decisão:** QW-2 consulta RAW diretamente. Menos ETL, menos bugs, mais honesto.

---

```

```

**Princípio:** RAW é source of truth. QW-2 é transform. Topic files são output.

## 3. QW-2 — RAW → Topic File Pipeline

### 3.1 Filtros de Qualidade (ANTES do routing)

Primeira coisa: descartamos o que não vale processar.

```python
def should_skip(claim: dict) -> tuple[bool, str]:
    # 1. DONE card notifications — não é decisão
    if "foi concluído" in text and "lista:" in text:
        return True, "Trello DONE card"

    # 2. Texto curto demais
    if len(text) < 50:
        return True, "text too short"

    # 3. Confiança baixa
    if confidence < 0.75:
        return True, f"low confidence {confidence}"

    # 4. TLDV sem decisões registradas
    if "sem decisões registradas" in text.lower():
        return True, "no decisions in transcript"

    return False, ""
```

**Garantia:** As 482 Trello DONE cards são descartadas no primeiro gate. As 55 decisões TLDV passam.

### 3.2 Routing (Inference Pass)

Para cada claim que passou nos filtros:

**TLDV:**
- Meeting name → project/topic
- Transcript excerpt → tags
- Tenta extrair `topics` do transcript se disponível

**Trello:**
- Board name → project
- Card title → subject
- Labels → tags

**GitHub:**
- Repo → project
- PR title → subject
- PR body → decision content

**Routing rules (case-insensitive):**
```
bat, kaba, bot         → bat-conectabot-observability.md
tldv, memory, livy,
openclaw, gateway      → livy-memory-agent.md
delphos, vistoria     → delphos-video-vistoria.md
forge                  → forge-platform.md
evo, evolution         → livy-evo.md
4d, imobi             → 4d-imobi.md
hydra                  → hydra-evolution.md
```

**Fallback:** Se nenhum match → `general.md` (ou log warning + skip)

### 3.3 Topic File Write (Direct)

QW-2 escreve **diretamente** nos topic files — sem pending, sem approval para claims de alta confiança.

```python
def write_decision(topic_file: str, decision: dict):
    # Append as blockquote no topic file
    entry = f"""
### {decision['date']} — {decision.get('source', 'unknown')}

> {decision['text']}

- **Source:** {decision['source_ref']}
- **Confidence:** {decision['confidence']}
- **Tags:** {', '.join(decision.get('tags', []))}
"""
    with open(topic_file, 'a') as f:
        f.write(entry)
```

### 3.4 Cursor (Incremental por source)

Mantém cursor por source em `.research/qw2/last_seen_<source>.json`:

```json
{
  "tldv": "2026-05-23T10:00:00Z",
  "trello": "2026-05-23T10:00:00Z",
  "github": "2026-05-23T10:00:00Z"
}
```

- Lê só items onde `updated_at` / `merged_at` / `closed_at` > cursor
- Atualiza cursor após processar cada source
- Se source não tem API query por date → usa cursor de "último ID visto"

## 4. QW-3 — Exceções e Revisão (Minimal)

### 4.1 O que ainda precisa de approval?

Nem tudo é write direto. QW-3 cobre:

| Caso | Condição | Ação |
|---|---|---|
| **Decisão TLDV ambígua** | `confidence < 0.85` E texto não é trivial | DM Lincoln |
| **Topic inferido como `general`** | routing falhou | DM Lincoln |
| **Trello sem board claro** | source_ref não identificável | DM Lincoln |

**O que NÃO precisa mais de approval:**
- Trello DONE cards → descartados no filtro (nem chegam)
- TLDV high-confidence (≥0.85) → direto
- GitHub PR decisions → direto

### 4.2 Routing DM vs Silencioso

| Condição | Ação |
|---|---|
| `confidence < 0.85` E `source == tldv` | DM com ✅aprovar/❌rejeitar |
| routing falhou | DM com topic sugerido |
| ≥ 1 decision routing failed | agrupar num DM só |

### 4.3 DM Format

```
🔍 Decision pending — нужна review

"Decisão aqui"

Source: TLDV | Confiança: 78% | Topic: bat-conectabot
[✅ Aprovar] [❌ Rejeitar] [⏭️ Skip]
```

### 4.4 Fallback: QW-3 pode escrever topic files

Se Lincoln aprova, QW-3 executa o write.

## 5. QW-2 → QW-3 Interaction

```
QW-2 run
  ├─ Para cada RAW item:
  │    ├─ Filtro (skip se não passou)
  │    ├─ Routing
  │    └─ Confidence >= 0.85?
  │         ├─ SIM → write_direct(topic_file)
  │         └─ NÃO → write_pending(pending/<id>.json)
  └─ QW-3 triggered

QW-3 run
  ├─ Ler pending/
  ├─ Para cada:
  │    ├─ DM Lincoln
  │    └─ Aguarda callback
  └─ Se aprovado → write_direct
     Se rejeitado → archive
```
