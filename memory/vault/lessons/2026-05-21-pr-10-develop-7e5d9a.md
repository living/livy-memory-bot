## O que aconteceu
Este PR adiciona um warm-up pós-deploy nos workflows de deploy do cronjob (homolog e produção) para forçar a inicialização do App Service após publicar o pacote. Também ajusta o comando de start do cronjob, garante a criação automática do container no Azure Storage antes do upload e inicializa/atualiza o status de job de download ao salvar configs no dashboard-api.

## Decisão / Solução
Foi decidido implementar um warm-up utilizando um sleep e tentativas com curl após o deploy, para reduzir falhas por cold start. O comando de start do cronjob foi alterado para alinhar a execução com o artefato buildado. Além disso, foi adicionado um passo para garantir a criação do container no Azure Storage antes do upload e a inicialização do status do job de download.

## Lessons
- Implementar um warm-up pós-deploy pode aumentar a confiabilidade do serviço, evitando falhas de inicialização.
- Alinhar o comando de start com o artefato buildado é crucial para garantir que o ambiente de produção se comporte como esperado.
- Garantir a criação do container no Azure Storage antes do upload previne erros que podem interromper o fluxo de trabalho.
