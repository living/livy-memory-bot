## O que aconteceu
Foi realizado um ajuste no formato de data enviado e armazenado ao editar a vigência da garantidora no módulo Chatboard → Condomínio. A data, que antes era salva como `YYYY-MM-DD`, agora inclui um timestamp fixo com timezone: `YYYY-MM-DDT00:00:00-03:00`. O objetivo é evitar inconsistências de data devido a fusos horários e padronizar o payload.

## Decisão / Solução
A decisão foi implementar uma string de data no formato ISO, fixando a hora em `00:00` e o offset em `-03:00`, para garantir que o backend e o frontend interpretem a data de forma consistente, evitando problemas de interpretação de data por diferentes fusos horários.

## Lessons
- Sempre que trabalhar com datas, considere a inclusão de informações de timezone para evitar ambiguidades.
- Padronizar o formato de dados entre frontend e backend é crucial para a consistência do sistema.
- Testes em diferentes fusos horários são essenciais para garantir que a aplicação se comporte corretamente em todas as situações.
